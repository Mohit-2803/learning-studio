SAY IT IN YOUR OWN WORDS

Four interview scenarios

Pause before opening the notes. Explain your approach aloud, then compare the points a clear answer should cover.

The CLI is installed, but Docker says it cannot connect. What do you check?

Separate client from Engine. Check daemon state and selected context, then verify with docker info. Explain that docker --version does not prove the daemon is reachable.

The API process is running, but a browser cannot reach it. How do you investigate?

Check container status and logs, confirm the app listens on the expected container port and interface, inspect the host-to-container mapping, then test from the host. EXPOSE alone does not publish a port.

A database container was replaced and its data disappeared. What should the design use?

Use a named volume mounted at the database data path. Explain that the volume has its own lifecycle and that Compose down normally keeps named volumes unless asked to remove them.

How would you prepare a Node image for a release?

Discuss a multi-stage build, small supported runtime base, non-root user, ignored local secrets, versioned image tag or digest, health signal, and a deployment platform that supplies runtime secrets.
